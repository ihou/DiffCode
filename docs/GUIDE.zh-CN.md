# DiffCode 使用说明

[← 返回简介](../README.zh-CN.md) · [English README](../README.md)

一个只做一件事的 macOS 原生工具：**看 Git 变更**。不需要为了看一眼改动而启动整个 IDE。

- 平时只读：刷新、diff、搜索都不写仓库，也不占用 `index.lock`，可以和 IDE、命令行同时开着。只有你在 diff 里改字，或者主动回滚、删除、提交、切换分支、拉取推送、Stash、改写历史时才会写。
- 看到就改：diff 右侧（工作区那一侧）可以直接打字，纯文本原地修改，停手约 1 秒自动保存，`⌘Z` 撤销。
- 看完顺手处理：整个文件回滚、单处改动回滚、删除新增的文件，都可以撤销；勾选文件直接提交，也可以只提交文件里的几处改动、甚至几行；刚提交的也能撤销，也能修改上一次提交（Amend）。
- 分支与远程：检出、新建分支、获取 / 拉取 / 推送；本地改动挡路时自动暂存再恢复。拉取冲突了，在合并视图里一键采用某一边，标记解决后提交合并。
- 改写历史：提交右键 Cherry-pick、Revert、「将当前分支重置到这里」；分支右键合并到当前分支、变基、重命名、删除。每一步完成后的提示里都有「撤销」。
- Stash：把改动暂存起来，在 Stash 列表里查看每个 stash 改了什么，再应用、弹出或删除（删除也能撤销）。
- Git 树：点侧栏里项目名下面的分支名，下拉框里看所有分支和提交图，不额外占一栏；右键检出、新建分支、合并、变基、重命名、删除，底部一排获取 / 拉取 / 推送。
- 追溯与历史：行号旁边打开逐行追溯（git blame），点一下就跳到那次提交；看整个文件或选中几行的历史，跟着重命名走。
- 审 agent 的活：「与分支比较」把工作区和某个分支的分叉点（或任意提交）比较，已提交的和没提交的改动一起列出来，一次看完；也可以挑两个提交互相比较。
- 内置终端：在底部并排开多个终端，直接在里面跑 coding agent，改动实时出现在上方的 diff 里。
- 原生 Swift + AppKit。第三方依赖只有终端模拟器 [SwiftTerm](https://github.com/migueldeicaza/SwiftTerm)，官网版另有自动更新用的 [Sparkle](https://sparkle-project.org)；它们的许可证随应用分发，见「关于 DiffCode」。
- 需要 macOS 14 及以上，以及系统里可用的 `git`。

## 编辑

diff 右侧显示的是工作区里的文件，点进去就能改——纯文本原地修改，不做代码补全。左侧（HEAD）和「提交历史」里的 diff 只读。合并视图里也能改：在新增行和上下文行上打字，删除的行只用来看。项目文件树里点开的普通文件同样可以改，改完它就成了一个有变更的文件。

- **保存**：停手约 1 秒自动保存；切换文件、窗口失去焦点、切到别的应用，以及提交、回滚之前都会先保存；`⌘S` 立即保存。标题栏文件名旁的圆点表示还有没写入的修改。
- **原样写回**：在原文件上写入，权限（比如可执行位）不变；编码（UTF-8 / UTF-16 / GB18030，带不带 BOM）、换行符（LF / CRLF，混用的文件逐行保留）、末尾有没有换行都保持原样，没改的地方逐字节不变。
- **diff 跟着变**：打字时改动色带立刻跟上，停手 0.15 秒后由 git 重新算出精确的 diff。把一处改回和 HEAD 一样，它就从 diff 里消失；整个文件改回去，文件会从「本地变更」里消失。
- **常用键**：`⌘Z` / `⇧⌘Z`（连续输入算一步；同一个文件切走再回来还能接着撤销），没有选中时 `⌘C` / `⌘X` 复制 / 剪切整行、整行粘贴到光标所在行的上方，`⌘⌫` 删除行，`⇥` / `⇧⇥` 缩进，回车自动缩进，`Home` 在行首和第一个非空字符之间切换，中文输入法组字。逐处回滚在编辑时照样可用，同样能 `⌘Z`。

**和 agent 同时改同一个文件**：每次写入前先确认文件还是上次读到 / 写入的样子。你没有未保存的修改时，别的程序改了文件就直接载入新内容；有未保存的修改时，载入对方的版本，你的修改按一次 `⌘Z` 就能找回。不会悄悄覆盖任何一方。

**不能编辑的文件**（标题栏显示锁和原因）：没有写入权限或在 Finder 里锁定的、符号链接、超过 4 MB 的、有超长行的，以及无法原样写回的（比如含有不成对的 `\r`）。

**保存失败时修改不会丢**（比如磁盘满了）：修改留在屏幕上，并提示原因；这时切到别的文件，修改会暂存在内存里，再打开这个文件时恢复并重新保存；如果在这期间文件被别的程序改了，就按上面的规则处理。退出时如果还有没保存成功的修改，会列出是哪些文件并先确认。

## 回滚与删除

下面三件事会改动工作区里的文件，都要你主动触发，确认框里会列出涉及的文件：

- **回滚文件**：在「本地变更」或文件树里选中文件（可以多选，也可以选目录或整个分组），右键「回滚…」、点列表上方的 ↶ 按钮，或按 `⌥⌘Z`，确认后恢复成 HEAD 的内容。已 `git add` 的新文件只是取消暂存，文件留在磁盘上；重命名会恢复原名并去掉新名字。
- **回滚一处改动**：diff 里每处改动旁边有一个 ↶ 按钮（并排视图在中间的连接带上，合并视图在右侧），右键菜单里也有「回滚这处变更」；键盘焦点在 diff 里时 `⌥⌘Z` 回滚当前这一处。不弹确认，直接生效，底部提示里可以点「撤销」。
- **删除新增的文件**：只对未跟踪和新增（还没提交过）的文件有效，`⌫` 或右键「删除…」，确认后移到废纸篓，不是直接抹掉。

`⌘Z` 撤销最近的一次（最多保留 20 步，只在本次运行期间有效）。撤销前会检查文件在这之后有没有再被改过——被你或 agent 改过的文件不会被覆盖，会跳过并提示。删除的文件即使过了撤销期也还在废纸篓里。

几个保守的选择：动手前按 HEAD 此刻的状态重新判断，而不是按列表上那一刻的状态——文件刚被提交过就不会被当成新文件删掉；逐处回滚前会重读文件，和 diff 上显示的内容对不上就不动手，刷新后再来；文件名按字面传给 git，名字里有 `*`、`?` 不会误伤别的文件；子模块不处理；UTF-16 文件只能整个回滚，不能逐处回滚。

## 提交

「本地变更」列表的每一行前面有勾选框，底部是提交说明输入框，「提交」按钮在框内右下角。拖动输入框上方的分隔线可以调整它的高度，下次打开还是这个高度。

- **勾选**：修改、删除、重命名和已暂存的新文件默认勾选，未跟踪的文件默认不勾。勾目录或分组会勾上其中所有文件；选中几行按 `空格` 一起切换。
- **提交**：`⌘K` 跳到提交说明（焦点在终端时 `⌘K` 仍是清空终端），写好后 `⌘↩` 或点框里的「提交」。只提交勾选的文件（`git commit --only`），暂存区里其余的内容保持原样；勾选的未跟踪文件会先加入，提交失败时恢复成未跟踪。
- **钩子照常运行**：pre-commit、commit-msg 等失败时，弹框里显示 git 的原始输出，勾选和提交说明都保留，改完再提交。
- **只提交一部分**：diff 里每处改动旁边有一个勾选框（并排视图在中间连接带的左端，合并视图在右侧 ↶ 按钮的左边）。取消勾选的改动这次不提交，显示为淡色；在 diff 里选中几行，右键「不提交选中的行」/「提交选中的行」可以细到行——改过的行连同对面的旧行一起处理，这一行就保持 HEAD 的样子。列表里这个文件的勾选框变成「−」，提交面板注明「N 个部分提交」，行数统计也只算要提交的部分。
  - 提交在一份单独的临时暂存区里完成：暂存区原有的内容和工作区都不动，没提交的部分留在工作区里，下次再提交。
  - 在 diff 里编辑后，选好的行跟着内容移动；文件被别的程序改得对不上时会拒绝提交并请你再看一眼，不会提交错的行。
  - 忽略空白时不显示这些勾选框（看不到的改动没法挑）；合并 / 变基进行中也不显示（git 只能整个提交合并）。
- **撤销提交**：提交后底部提示里有「撤销提交」，输入框左下角也有「撤销 <哈希>」。只对本次运行在这里做的最后一次提交有效；分支之后又动过（又有新提交、切了分支）或这个提交已经推送到远程，就不撤销。撤销后改动回到列表（处于暂存状态），提交说明也回到输入框。
- **修改上次提交（Amend）**：勾选输入框左下角的「修改上次提交」（或 Git 菜单「修改上次提交 (Amend)」，工作区干净时也能用），说明框换成上一次的提交说明，按钮变成「修改提交」。勾选的文件（包括只提交一部分的文件）并入上一次提交；一个文件都不勾，就只改提交说明，暂存区里的其他内容不会被带进去。取消勾选时，说明框里原来写到一半的内容会回来（前提是你没改动填进来的说明）。上一次提交已经推送到远程时，框上方会提示：修改后只能强制推送。修改后提示里的「撤销修改」把被替换的那次提交找回来，新加入的改动留在暂存区。
- **提交并推送**：`⌥⌘K`，提交成功后接着弹出推送确认。

不做交互式 rebase，需要时在内置终端里用 git。

## 分支、拉取与推送

- **检出**：Git 树里右键分支「检出」。远程分支会建一个同名的本地分支跟踪它；标签和提交（「检出此版本…」）以分离 HEAD 检出，会先确认。本地改动和目标分支冲突、git 拒绝切换时，列出这些文件并提供 Smart Checkout：先暂存（stash），切换后再恢复；恢复时冲突就按下面的合并冲突处理。
- **新建分支**：Git 菜单「新建分支…」，或在分支 / 提交上右键「从它新建分支」「在此新建分支」。输入时即时检查名字是否合法、是否重名，`↩` 创建并切换。
- **拉取**（更新项目）：本地和远程分叉时问你合并还是变基；本地有改动时提供自动暂存（autostash）再拉。拉完提示拉下来几个提交。
- **推送**：先列出将要推送的提交再确认；新分支第一次推送会设置上游；远程有你没有的提交而被拒时，提示先拉取。
- **强制推送**：修改过、变基过或重置过已经推送的提交后，本地分支和远程各有对方没有的提交。这时推送会列出远程那边多出来的提交，默认建议拉取；如果是你有意改写的，可以点「强制推送…」，再确认一次。用的是 `git push --force-with-lease`，并且锁定为刚才列给你看的那个远程提交：上次获取之后有人推送过，就什么都不覆盖。main 和 master 不提供强制推送。
- **合并、变基**：Git 树里分支的右键菜单「将 X 合并到 当前分支」「将 当前分支 变基到 X」，本地分支、远程分支都可以。快进、合并提交都用 git 自己的说明；本地改动挡路时提供「暂存后继续」（`--autostash`）；遇到冲突按下面的合并冲突处理。要变基的提交里有已经推送的，会先提醒你之后只能强制推送。完成后提示里的「撤销」把分支放回原处（之后分支又动过，或新的提交已经推送，就不撤销）。
- **重命名、删除分支**：本地分支右键「重命名…」（继续跟踪原来的远程分支）、「删除」（当前分支不能删）。分支上有其他分支都没有的提交时，git 会拒绝，DiffCode 列出这些提交，确认后才强制删除；删除后提示里的「撤销」在原来的提交上把分支建回来，连同跟踪关系。远程分支右键「从 origin 删除…」，确认后删除服务器上的分支，「撤销」会把它推回去；main 和 master 不提供删除。
- **获取**：获取所有远程的更新，提示有几个提交可以拉取。
- 认证用 git 自己的凭据助手和 SSH agent，不弹密码框；需要密码时提示你在终端里先登录一次。运行中侧栏的分支名旁边显示进度，Git 树底部可以停止。

## 合并冲突

- 拉取、合并、变基、拣选、还原或恢复暂存出现冲突时，「本地变更」顶部的横幅显示正在进行的操作和剩余的冲突数，带「继续」「中止」；变基、拣选和还原还有「跳过」，略过停下的这个提交接着做（有已解决的改动会被丢弃时先确认）。
- 冲突文件的 diff：右边是工作区里带冲突标记的文件，左边可以在 HEAD / 共同祖先 / 传入版本之间切换。每处冲突的 `<<<<<<<` 行上有「保留 HEAD」「采用传入」「两者都要」，点了直接改写，可以 `⌘Z`；也可以手动改。
- 冲突文件右键：「保留 HEAD 的版本」「采用传入的版本」（整个文件），「标记为已解决」（还有冲突标记时会先问）。
- 全部解决后：合并的话，提交框里预填了 git 准备好的合并说明，点「提交合并」；变基的话，在横幅上点「继续」。

## Git 树

点侧栏里项目名下面的分支名（鼠标移上去会高亮），或按 `⌥⌘B`，在下拉框里查看这个项目的分支和提交图，不额外占一栏，`Esc` 或点外面关闭。点的是别的项目的分支时会先切到那个项目；侧边栏隐藏时，`⌥⌘B` 的下拉框出现在窗口左上角。

- 左边：「全部分支」、本地分支（当前分支在最前，带 `↑领先 ↓落后`）、远程分支、标签，顶部可以筛选。点哪个，右边就只显示它的历史。
- 右边：提交图，合并提交是空心点，当前 HEAD 带圆环；`↑↓` 选择，`⇥` 在两栏之间切换，`↩` 或双击在「提交历史」里打开这个提交。右键提交：在此新建分支、检出此版本、与工作区比较、拣选（Cherry-pick）、还原（Revert）、将当前分支重置到这里、复制哈希和提交信息；`⌘` 点选两个提交，右键比较这两个提交。
- 左边分支的右键菜单：检出、从它新建分支、比较、合并到当前分支、把当前分支变基到它、重命名、删除。
- 底部：获取、拉取（显示可拉取的提交数）、推送（显示待推送的提交数）；运行时显示进度，可以停止。
- 一次加载 400 个，往下滚自动加载，最多显示最近 1200 个提交；更早的历史在「提交历史」里查看和搜索。

## 改写历史：Cherry-pick、Revert、Reset

在「提交历史」或 Git 树里右键提交：

- **拣选到当前分支（Cherry-pick）**：把这个提交的改动作为新提交接到当前分支上。`⌘` 点选多个提交时按从旧到新的顺序依次拣选；合并提交、当前分支已经有的提交（包括以前拣选过、改动已经在里面的）会自动略过，并在提示里说明略过了几个。当前分支已经有的提交，菜单项是灰的。
- **还原提交（Revert）**：新建一个提交来抵消它的改动，用 git 的「Revert "…"」说明；多选时从新到旧依次还原。只能还原当前分支上的提交。
- **将当前分支重置到这里**：先列出将要离开当前分支的提交，再选模式——Soft（这些提交的改动回到暂存区）、Mixed（变回本地改动，默认）、Hard（连同已跟踪文件的本地改动一起丢弃，选中时按钮变红）、Keep（丢弃这些提交但保留本地改动，冲突时 git 拒绝）。其中有已经推送的提交时会特别提醒。
- **撤销**：上面这些操作，以及合并、变基，完成后提示里都有「撤销」，把分支放回操作前的提交。Hard 重置前会先把本地改动存一份（`git stash create`，不进 Stash 列表），撤销时一起恢复。之后分支又动过，或者撤销会丢掉已经推送的提交，就不撤销；撤销时你后来做的本地改动保留不动。
- 冲突时停下来，横幅里继续、跳过或中止（见「合并冲突」）；本地改动挡路时，按 git 的提示先提交或 Stash。

## Stash

- **Stash 改动**：Git 菜单「Stash 改动…」或 Stash 列表顶部的「Stash 本地改动…」。可以写一句说明（不写就用 git 默认的「WIP on 分支」）；有新文件时可以勾选「包括新文件」（只有新文件时默认勾上）。完成后提示里的「撤销」把改动原样放回来。
- **Stash 列表**：「本地变更」标题栏的 Stash 按钮，或 Git 菜单「Stash 列表…」。按时间从新到旧列出，显示说明、所在分支、是否带新文件，可以输入筛选。`↩` 打开一个 stash：「本地变更」列出它改了哪些文件（相对它当时所在的提交，新文件单独列出），点文件看 diff。
- **应用 / 弹出 / 删除**：查看 stash 时，列表上方的横条里有「应用」（改动放回工作区，stash 留在列表里）、「弹出」（放回后从列表删除）、「删除…」（确认后删除，提示里的「撤销」可以把它放回列表）。和本地改动冲突时，冲突文件按合并冲突处理，stash 保留在列表里。按 stash 的提交找它，列表在别处变动过也不会用错。

## 追溯、历史与比较

**逐行追溯（Annotate）。** 点 diff 标题栏的追溯按钮，或在 diff 里右键「逐行追溯 (Blame)」。行号左边多出一栏，每段连续来自同一次提交的行标一次「日期 作者」，左侧色条越亮表示越新；还没提交的行留空。鼠标停在上面显示完整的提交信息，点击就在「提交历史」里打开这个文件的历史、选中那次提交。它是一个开关：打开后换文件也一直显示，再点一次关闭。编辑时跟着走：改过的行立刻变成「未提交」，保存后重新读一遍。看提交的 diff 时追溯的是那次提交里的文件。

**文件的历史。** 在「本地变更」、文件树、某次提交的文件列表或 diff 里右键「查看历史」：「提交历史」只列出改过这个文件的提交，跟着重命名一直往前找；点开每个提交显示的是这个文件在那次的改动（文件当时叫什么名字就用什么名字）。列表上方的标签显示正在看谁的历史，点 × 回到完整的提交历史。搜索框照常可用。

**选中内容的历史。** 在 diff 里选中几行（或者只把光标放在某一行），右键「查看所选内容的历史」：只列出改过这几行的提交（`git log -L`）。行号会先换算到 HEAD 里对应的位置——工作区里上面插入或删掉了几行也没关系；全是还没提交的新行时会直接提示。

**与分支比较，用来审 agent 的活。** 让 agent 在一个分支上干了一阵（提交了几次、手上还有没提交的），想一次看完它到底改了什么：在「查找操作」（`⇧⌘A`）里运行「与分支比较…」，选 `main`。「本地变更」就会列出从和 `main` 分叉的那个提交到现在工作区的全部差异，已提交的和没提交的都在里面，顶部的横幅说明正在和谁比较，点 × 回到平常的本地变更。

- 选分支：和分叉点比较（`git merge-base`），只看这个分支自己的改动，不会混进 `main` 后来的提交；选标签或输入一个提交哈希：直接和那个提交比较。
- 菜单栏的 Git 菜单里也有「与分支比较…」。Git 树里分支的右键菜单有「查看自与 main 分叉以来的变更」和「与工作区比较」，提交的右键菜单（Git 树和「提交历史」里都有）有「与工作区比较」。
- 比较时 diff 右侧仍然是工作区的文件，可以直接改；回滚和提交只针对平常的本地变更，所以比较时不显示。分支往前走了，刷新时会重新计算比较的起点。

**比较两个提交。** 在「提交历史」或 Git 树里 `⌘` 点选两个提交，右键「比较 X 与 Y」：「本地变更」列出较早那个到较新那个之间的全部差异，两边都只读。

## 终端

（只在官网下载版里有；App Store 版在沙盒里运行，没有内置终端。）

终端启动的是你的登录 shell（读取 `~/.zprofile`、`~/.zshrc` 等），工作目录是当前项目，每个项目有自己的一组终端，切换项目时各自保留。在里面运行的程序拥有和你在 Terminal.app 里一样的权限——终端里的 agent 可以改文件，改动会立刻出现在「本地变更」里，不满意的地方可以直接在 diff 里回滚。

- 从 Finder 把文件拖进终端，输入的是转义好的路径；文件树和 diff 的右键菜单里有「把路径插入终端」。
- 在 diff 里选中几行按 `⌥⌘T`，输入的是 `路径:起始行-结束行`，方便直接指给 agent 看。
- 终端里有程序在运行时，关闭终端或退出 DiffCode 会先确认。
- 每个终端保留 2000 行回滚。

官网版菜单里有「检查更新…」，只有 Info.plist 里同时有 `SUFeedURL` 和 `SUPublicEDKey` 时才启用。这两项来自 `release/macos/AppInfo.local.env`：这个文件在的话，`Scripts/build-app.sh` 的本机构建也会写进去、也会检查更新；`swift run` 不检查更新。App Store 版只能访问用户选择过的文件夹，用 security-scoped bookmark 跨启动保留；git 用的是系统里的二进制（Command Line Tools、Xcode 或 Homebrew），找不到时提示安装。

SwiftTerm 固定在 1.11.2：之后的版本带 Metal 着色器，只装了命令行工具、没有 Metal Toolchain 的机器编译不了。DiffCode 用的是它的 CoreGraphics 渲染路径，不需要 Metal。

DiffCode 只用 SwiftTerm 的终端模拟和绘制，shell 进程和伪终端的读写是自己做的（`Sources/Dif/App/PTY.swift`）。SwiftTerm 自带的 `LocalProcess` 用 `DispatchIO` 读输出，每几百字节就分配一块新缓冲：刷 1.2 万行日志要占 200 MB，40 万行到过 4 GB。DiffCode 读进一块复用的缓冲，主线程来不及解析时暂停读取，让刷屏的程序慢下来，而不是把输出堆在内存里。

## 为什么省内存、滚动快

**不重绘。** 代码文本只光栅化一次，切成每 8 行一块的小图块（宽度只到该块最长的一行），之后滚动只是 GPU 合成器移动这些图块；变更色带、词级高亮、搜索命中、选区是文字下方的纯色图层，连接带是矢量图层。滚动一帧的开销是几次图层位移，加上刚滚进视野的那几行的光栅化。

这里的「GPU 加速」指 Core Animation 合成预先光栅化的图块，不是自己写的 Metal 字形渲染器——对一个 diff 查看器来说，前者已经让每帧开销远低于刷新间隔，同时保留了系统级的文字渲染质量。

**不常驻。** 没有索引，没有后台进程，没有语言服务。diff 由 `git diff --no-index --diff-algorithm=histogram` 计算，搜索交给 `git grep`，文件列表来自 `git ls-files`。

**紧凑的堆。** 打包时在 Info.plist 里给 DiffCode 自己设置 `MallocSpaceEfficient=1`（不传给终端里启动的程序），分配稍慢一点，换来更小、更少碎片的堆：启动内存从约 38 MB 降到约 30 MB。

**不锁仓库。** 所有 git 调用带 `GIT_OPTIONAL_LOCKS=0`，刷新和 diff 不会去拿 `index.lock`。只有回滚 / 删除 / 提交、切换分支和拉取那一下需要写索引；如果这时另一个 git 进程正占着锁，操作会失败并提示，文件保持原样（一次回滚很多文件、中途才失败的话，已完成的部分可以用 `⌘Z` 撤回）。

| 逐行追溯，2.4 万行的文件 | 约 100 ms |
| 文件历史（跟随重命名，177 个提交）/ 20 行的行历史 | `git log` 本身约 165 ms / 约 135 ms |
| 与 500 个提交之前比较（541 个文件有差异） | 约 1 s（rename 检测），列表内存多约 10 MB |
| 加入 Amend、Stash、改写历史之后（与 0.2.0 对比，同一仓库同一操作） | 静置多约 0.4 MB；提交历史、Git 树持平 |
| 内存，打开 Stash 列表 / 重置对话框 | 多约 1 MB / 约 2 MB，关闭后约 1.5 MB，反复打开不再增长 |

终端里运行的程序（shell、agent）是独立进程，它们的内存不算在 DiffCode 里。

120 Hz 屏幕的帧预算是 8.3 ms。内存为 `vmmap` 报告的 physical footprint。复现方法：

```bash
swift build -c release -Xswiftc -DDIF_HOOKS
DIF_ACTIONS="select:path/to/File.kt" DIF_BENCH=1 .build/release/Dif /path/to/repo
```

## 目前不做的

只支持 macOS。编辑只做纯文本原地修改：没有代码补全、多光标、查找替换，也不能新建文件。不做交互式 rebase、标签管理、子模块，需要时在内置终端里用 git。会写仓库的只有上面说的编辑、回滚、删除、提交，以及你主动发起的检出、新建分支、拉取、推送、Stash、改写历史、分支管理和冲突处理。不会打开外部编辑器。
